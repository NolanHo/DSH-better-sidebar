### Unreleased

- 🗂 **The work-details control line now speaks the main pane's language, and the fork banner stops offering an empty disclosure.** The fold line used to carry a plugin-invented caption; the host labels this same control from `message.turnProcess.*`. A settled turn with a measured duration now reads "Completed in 1.2s" (the duration is that turn's own `turn/end` measurement, formatted by the same `formatDurationMs` the usage line prints, so the two can never disagree), a settled turn without one reads "Completed", and a running turn reads "Running…" and stays open. The fork banner is now expandable ONLY when there really is a pre-fork answer: a fork summarised with just the question (or with neither part) degrades to a single static card, so it no longer opens onto nothing. `sideChatWorkDetails` retires from all 21 dictionaries; the three new copies are in all 21.
  - 🧪 `tests/sidechat-work-details-mode.spec.tsx` (all three modes show "Completed in 4s" and never "Running…", the running line says "Running…" and never "Completed", and a turn without `turn/start` shows plain "Completed"); `tests/sidechat-fork-point.spec.tsx` (the existing cases: a fork with an answer is still expandable).

- ✂️ **The fork banner no longer cuts the parent's answer into half a sentence.** The answer used to be hard-truncated at 240 characters, so expanding it stopped mid-word. It is now carried up to **4000 characters** whole (the expanded body scrolls), and any cut lands on a BOUNDARY: the last line break (a whole paragraph survives) → sentence-ending punctuation (`。！？` and `. ! ? …`, punctuation kept) → the last whitespace (a word is never split) → a hard cut only when the whole text is one over-long word. The `…` appears only when something was really lost and counts toward the cap (`user` stays a 400-character single-line summary, cut the same way); a text that fits is carried verbatim with no mark at all.
  - 🧪 `tests/sidechat-fork-route.spec.ts` (the answer is carried complete well past the old 240 cap, all three boundary kinds are honoured without splitting a word, and a fitting text comes back byte-identical with no mark).
- 🎨 **The three "debt" tokens recorded last time are renamed to spellings the host actually defines, restoring colours, borders and font sizes that never painted.** `--dsw-alias-danger` / `--dsw-alias-bg-l2` / `--dsw-font-xs-regular-13` are defined nowhere in the host theme, so the 11 declarations that referenced them were invalid at computed-value time — the side chat's error banner copy and the failed row's copy/border, the unread dots on sidebar tabs and entries, the terminal panel's status bar and error-block background, and the changes pane's markdown body and graph caption font shorthand all painted nothing (or fell back to the browser default). Only the token names changed: no other property, selector or formatting in those rules was touched. The guard's debt list is now empty and pins the three retired spellings as regressions that fail the suite if they come back, and the typography contract records the one paint value that moved with them.
  - 🧪 `tests/css-host-tokens.spec.ts` (empty debt list, the three retired names pinned as regressions, every `var(--dsw-...)` reference resolves) and `tests/sidechat-typography-contract.spec.tsx` (the error banner and failed row paint through `--dsw-alias-state-error-primary`; the other 12 rules' typography snapshot is unchanged).
- 🧱 **The sidebar's borders that never appeared are back, with a static guard behind them.** A CSS custom property resolves at computed-value time, so an unknown name invalidates the WHOLE declaration — silently, with nothing to notice. Six declarations referenced `--dsw-alias-hairline`, which the host never defines (the model button, the guide line beside collapsible row bodies, the separator between adjacent code blocks, the composer's fallback border, and the fork banner's card edge plus its inner divider), so every one of those lines was simply absent. They now use the host's real `--dsw-alias-border-l1` / `-l2` by visual weight (the composer keeps `-l2-darkmode-thin`, only its fallback changed). `tests/css-host-tokens.spec.ts` scans every `var(--dsw-...)` in `src/client/**/*.css`: a reference without a fallback must name a host snapshot token or one the plugin declares itself. Three pre-existing debts of the same class (`--dsw-alias-danger` / `--dsw-alias-bg-l2` / `--dsw-font-xs-regular-13`) are listed with the host token that should replace them, and the list may only shrink — paying one debt without removing it fails the suite.

- 🌿 **The side chat says where it forked off the main conversation.** A side thread's log opens with the parent log as a fork seed, and `sidechat.events` cuts it at the last inherited `session/end-seed` marker — invisibly, so the transcript started on the side question with no hint of which main-pane question it continued, and the parent prefix never crosses the wire for the client to reconstruct. The FIRST pull now carries an additive `fork: { cutSeq, user?: {seq,text}, assistant?: {seq,text} }`: `cutSeq` is the cut marker's own seq (the same boundary the transcript cuts at), `user` is the last REAL user message before the cut (a replacement such as a compaction checkpoint is never presented as the reader's question, a runtime injection — `time-context`, `tmux-context`, `plugin:…` — is skipped too because it is logged as a user message the reader never typed, and an image-only prompt leaves the part out), `assistant` is the last assistant message's text blocks before the cut (reasoning never leaks), and each part keeps its opening (question ≤400 chars, answer ≤240). A delta pull carries no such field, and `events`/`live`/`pending`/`truncated` keep their shapes and values. The transcript renders a collapsed `<details data-sidechat-fork-point>` above the first row inside the scroller: the line reads "forked from the main session" plus the main-pane question and the parent session's title, and expanding it shows the pre-fork answer under its own heading. Both strings are in all 21 dictionaries.

- 🗂 **The side chat follows the main conversation's "work details" setting.** The main pane folds a turn's reasoning and tool rows behind one expandable control; the side chat read no preference at all, so the same conversation was a wall of process rows in the panel no matter what the reader had chosen. The transcript now reads `transcriptView` and `collapseTiming` from the host's public settings service (`ctx.get('configForms')` → `ui-chat`, a structural probe — no inject, no value-import of the settings package) and normalizes them exactly like the host (`normal` / `expanded` → `detailed`; a missing service, a form that is not ready, or an unusable value keep the client default — `detailed` on the Web, `standard` on the desktop shell). Under `compact` / `standard` / `detailed` every SETTLED turn's work rows (reasoning / tools) fold into one `<details data-sidechat-turn-fold>` (closed by default, its line carrying the host's turn copy, the rows still in the DOM); a turn that has not ended yet keeps the same control OPEN; `verbose` folds nothing at all. The question and the answer never enter the fold. `collapseTiming: next-input` leaves the newest completed turn open while the default `completion` folds it, and `standard` / `detailed` put the running tool/command or the first line of streaming reasoning on the control's tooltip where `compact` keeps the bare label. A settings change applies live (a subscription push re-renders the mounted transcript; no remount).

- 🧭 **Compaction and model retries are now visible, and a compaction checkpoint no longer impersonates a user message or injected context.** The checkpoint is a `user/message` with `surfaceOp: replace`, and the user branch had no replacement test, so `isContextInjectionMessage` classified it by `source.kind` alone: the moment history was compacted the transcript claimed context had been INJECTED, and expanding that row showed the whole shadowed summary as pasted text. The replacement test now runs BEFORE the injection predicate, so a replacement `user/message` is neither a user row nor an injection row. Only a landed checkpoint (`source.kind === 'compact-checkpoint'`) draws ONE `compaction` row (its seq is the checkpoint's, carrying the summary and the shadowed item/token counts from the metering event; the summary body sits behind a `<details>` and the line stays a label plus the counts), `compaction/start|summary|end` alone draw nothing, and a summary outside the window still leaves one non-blank row. Retries fold per `retryId`: `llm/retry` updates the row, `llm/retry-started` only flips it to `started` without adding one, and the row keeps the chain's first seq — reading as "retried N times" plus the provider's own failure text; an event without a `retryId` draws nothing and `mode: 'always'` invents no limit. All four strings are in the 21 dictionaries.
  - 🧪 `tests/sidechat-compaction-retry-rows.spec.tsx` (one row per transaction at the checkpoint, nothing without a checkpoint, one non-blank row when the summary is missing, the summary carried by the compaction row alone and never as the visible line, counts from the dictionaries; the retry chain folds into one row, `retry-started` adds none, `always` carries no limit, no `retryId` draws nothing, and the row reads "retried N times" with the provider failure).

- 🖼 **Image and file content blocks render in the side chat.** The mapping kept only `text` blocks, so a screenshot the reader attached, an image a tool produced, and a document handed to the model all vanished — the transcript claimed a text-only conversation. All three sources (a user message, an assistant message, a tool result) now render an `image` thumbnail, and the bytes come ONLY from `ctx.get('remote').session.attachment({ sessionId, attachmentId })` with `sessionId` = the thread's own id (a side thread is not a scope the client retained, so the host's `uiConversation.imageUrl` path rejects it): base64 → `Blob` (typed with the attachment's mediaType) → `URL.createObjectURL`, revoked on unmount. One request per attachment id, shared by every block naming it. A `file` block renders the host's name + size chip with NO RPC at all. A declined read, a carrier rejection, or a composition without a remote namespace renders the localized `sideChatAttachmentImageFailed` placeholder instead of a broken image, and a malformed block (no `attachmentId` or no `name`) is skipped without a request or a crash. Both strings are in all 21 dictionaries.
  - 🧪 `tests/sidechat-attachment-blocks.spec.tsx` (all three sources render a thumbnail, one request per attachment with a shared object URL, `uiConversation` is never used, all three failure modes render the placeholder and no `<img>`, the file chip reads zero bytes and uses the host size formatter, a malformed block is skipped, unmounting revokes every minted URL).

- 🔧 **A collapsed tool row no longer uses raw argument JSON as its summary.** `toolArgsSummary` only recognised `command` / `file_path` / `path` / `pattern` / `query` / `url` / `prompt` and otherwise fell back to the WHOLE raw arguments string — so a tool with an unfamiliar shape showed escaped quotes instead of anything readable. With no identifying key it now takes the FIRST string field (or the first array field's entries, in the object's own order), and an object with neither (all numbers/booleans/nested objects) gets an empty summary instead of JSON. An object that HAS an identifying key but left it blank, and arguments that are not an object at all (unparsable, or a bare array), still show the raw text — the key is the tool's own vocabulary, and for a non-object the raw text is all there is.
  - 🧪 `tests/sidechat-transcript.spec.ts` (`{"custom":"v"}` → `v`; an object with no string/array field yields a summary containing neither `{` nor `"`).
- 🔎 **grep / glob / web_search and web_fetch results now draw the host's structured cards.** Only bash / edit / write / read / present had cards; everything else — including the highest-frequency tools after bash — fell through to raw argument JSON next to raw output. The host does not parse that text either: it reads the `tool/result` `meta` and draws a real card, declining to the generic row whenever the shape is less than exact. The side chat now mirrors that narrowing — grep's `matches` / glob's `paths` become the host `SearchBlock` (`data-search`), web_search's `search` / web_fetch's `fetch` become the host `WebBlock` (`data-web`) — while a missing `meta`, a wrong `shape`, a missing or ill-typed field, or a FAILED result keeps today's labelled two-section row (arguments / result): never blank, never a half-built card. All card chrome comes from the dictionaries: the copy control reuses `copy` / `copied`, the count summaries are function labels (`{shown}` / `{total}` / `{files}`), and the 8 new keys are in all 21 dictionaries.
  - 🧪 `tests/sidechat-search-web-cards.spec.tsx` (one card per shape with the right content, eight non-conforming metas all fall back to the labelled row, a failed result never grows a card, the copy control uses dictionary copy).
- 🖼 **Images in the side chat enlarge into the host lightbox, like the main conversation.** The host wraps an `<img>` in its preview button and mounts `ImageLightbox` only when the surrounding `MarkdownDelegateProvider` supplies `fileImages` — the main conversation always did, the side chat only passed `openFile`, so the same screenshot enlarged in the main pane and did nothing here. The transcript's provider now supplies `fileImages` (`resolve` deliberately returns `undefined`: local images already travel through the pre-render media-URL rewrite, and declining is exactly what keeps an image LINK such as `[shot](a.png)` from growing a hover preview card). A remote image gains the host preview button (accessible name from `sideChatImageOpen`); activating it opens `ImageLightbox` (`role="dialog"` / `aria-modal` / `sideChatImageDialog`, close control `sideChatImageClose`), Escape dismisses it, and opening issues no request (it reuses the authored URL). All five strings — including the `loading` / `failed` failure copy — are in all 21 dictionaries.
  - 🧪 `tests/sidechat-lightbox.spec.tsx` (image sits in the preview button whose `aria-label` starts with the dictionary copy, activation mounts the dialog and Escape closes it, a declining `resolve` grows no hover preview, opening adds no request).
- 🔗 **Inline file mentions in the side chat are clickable — and only for files the thread actually produced.** In the main conversation `` `src/client/api.ts` `` is clickable because the chat view hands `MarkdownText` a `fileMentions` resolver; the side chat never passed one, so the same answer was dead text there. The transcript now rebuilds the same vocabulary from the thread's OWN rows: the target of the calls that actually produce a file (`write` / `edit` / `str_replace_editor`, the host's `mutationPath` set — `str_replace_editor` is judged by its `command`, so a read-only `view` does not count, and a FAILED call counts for nothing because failure now comes from the host's own `message.isError`, which a tool that throws a bare error also sets; what a `read` touched or a `grep` / `glob` searched is not production, and a directory would otherwise become an openable "mention") plus the delivery record's (`deliverables`) `files[].path`. A token that equals a path or its basename, and matches EXACTLY ONE produced path, becomes the host's mention control (its `title` is the resolved path, its accessible name `sideChatMentionOpen`); activating it goes through `openSidebarFile` → `openTab({ type: 'editor', path })`. An ambiguous basename (two `dup.ts`) and anything outside the set stay inert `<code>`. Resolving issues no request: the vocabulary is the thread's own rows. `sideChatMentionOpen` is in all 21 dictionaries.
  - 🧪 `tests/sidechat-file-mentions.spec.tsx` (produced basename and full path link, delivered files link, unknown and ambiguous tokens stay inert, activation opens the editor, opening adds no request).
- 🐞 **A send's cleanup only touches the thread that sent it.** `handleSend` cleared the composer unconditionally after `sidechat.prompt` resolved, while the view keeps ONE composer that is swapped per bound thread — so a reader who switched threads while the request was in flight (the host only logs a message when a turn claims it, so "sent but not finished" is the normal state) had the draft they had just typed in the other thread wiped by that cleanup: no error, no request, the words were simply gone. The cleanup is now scoped to the `sendThreadKey` the send started from: only that thread's draft is dropped, and the composer is cleared only while it still shows that thread.
  - 🧪 `tests/sidechat-send-race.spec.tsx` (draft survives on the newly bound thread when the response lands after the switch, the sending thread is still cleared, an unmoved binding clears as before).
- 📝 **A draft belongs to its thread, not to the tab.** The composer was one component-level `useState('')`, and re-binding only reset the transcript cache, the info badge and the reveal/follow state — never the draft. So half a question followed the reader into another thread: after an archive fallback or any re-delivery of `tab.meta.threadId`, thread A's text sat in thread B's composer and one Enter sent it to the wrong conversation. Drafts are now kept per bound thread id: another thread opens with its own (empty) draft, coming back restores it verbatim, a successful send clears only the sending thread, and a newly created thread starts empty without touching the existing ones.
  - 🧪 `tests/sidechat-draft-isolation.spec.tsx` (no carry-over across threads, restore on return, only the sending thread is cleared, new-thread isolation).
- 🔧 **A generic tool row no longer dumps raw JSON next to raw output.** Only bash / edit / write / read / present get structured cards; every other tool (grep, glob, web_search and every host tool this view does not know) fell through to two UNLABELLED `<pre>` blocks — a wall of escaped quotes. The collapsed line still shows the tool name plus the one-line argument summary (no raw JSON, no result), and the disclosed body now splits into two labelled sections: `Arguments` → the raw arguments, then `Result` → the raw output, each label before its own content. Dedicated cards are untouched. Both labels are in all 21 dictionaries.
  - 🧪 `tests/sidechat-tool-row-noise.spec.tsx` (summary-only collapsed line, label order in the body, the bash terminal card unchanged).

- ✂️ **A truncated transcript now says that earlier history is missing.** When `sidechat.events` capped its response at the newest 8000 events it left no marker, so the client rendered that tail as if it were the thread's beginning — the first thing the reader saw was an answer to a question that was not there, with nothing explaining the gap. The route now returns an ADDITIVE boolean `truncated` (`true` ⇔ the thread's own log exceeds the cap, i.e. the reader is looking at an incomplete history — a small delta poll on such a log reports it too, because the field describes the thread rather than one response; `events`/`live`/`pending` keep their shapes, so an older client parses the response unchanged), and the view renders a `sideChatTruncatedNotice` line inside the scroller above the first mounted row. It is chrome, not a row (no row hook, no row count), and a whole transcript — or an explicit `false` — shows nothing at all. Copy added in all 21 dictionaries.
  - 🧪 `tests/sidechat-truncation-route.spec.ts` (cap boundary, newest slice returned, the delta path never claims truncation, the response stays additive) and `tests/sidechat-truncation-notice.spec.tsx` (hint at the top of the scroller, dictionary copy, not a row, absent for a whole transcript or `false`).

- 🛑 **A stopped turn no longer just "stops growing", and an output-limit cut is explained.** `turn/end` only recognised `reason.kind === 'error'` and dropped every other ending, so pressing Stop made the transcript simply stop growing (a finished answer and a killed one looked identical) and a `max-tokens` cut looked like a normal finish. `aborted` / `interrupted` now leave a "this turn was stopped" line, `max-tokens` leaves "the output limit was reached — the answer is cut off" (two different sentences, because the reader's next action differs), and an attempt's terminal finish reason is deduped with the `turn/end` that repeats it (one row per turn). The error path and a normal completion are unchanged. Both sentences are in all 21 dictionaries.
  - 🧪 `tests/sidechat-terminal-rows.spec.tsx` (one terminal row per stop reason, its own sentence for max-tokens, attempt+turn/end dedupe, error/completed untouched, and the copy actually rendered).

- 🧠 **Side-chat reasoning renders as Markdown and reports how much thinking there is.** The reasoning body used to be `white-space: pre-wrap` plain text, so a model's `**emphasis**`, `- item` lists, `` `commands` `` and source links all showed their literal syntax — the last place the side chat looked nothing like the main conversation (whose reasoning is markdown). Reasoning now renders through the host's `MarkdownText`, the same component and the same `MarkdownDelegateProvider` surface as assistant prose: emphasis becomes `<strong>`, lists become `<li>`, inline code becomes `<code>`, and a local `[file](<path:line>)` link is claimed by the host and opens through `betterSidebar.openTab` at the referenced line. The collapsed summary shows `sideChatReasoningSummary` ({chars} characters of the raw text; a reasoning row carries no timing data, so no duration is invented).
  - 🧪 `tests/sidechat-reasoning-markdown.spec.tsx` (element rendering / link claimed and opened at its line / summary from the dictionary).

- ⌨️ **Shortcut and layout chords no longer send by accident.** The keydown path only looked at Enter + Shift + the IME signals, so `Alt+Enter` (Option is how a macOS reader types an accent or a symbol), `AltGraph+Enter` (a layout-switcher gesture on several layouts) and `Ctrl+Meta+Enter` submitted and wiped the draft; `Shift+Ctrl/Meta+Enter` was neither submitted nor consumed, leaving a stray newline; holding Enter down machine-gunned one send per repeat. The composer now honours the host keymap's first line: modifier chords (Alt / AltGraph / Ctrl+Meta / Shift with Ctrl or Meta) neither submit nor break the line (the event is consumed). A `repeat` keydown never submits, but whether it is CONSUMED follows the gesture it repeats: repeats of the submit gesture (`enter` mode's bare Enter, `mod-enter`'s Cmd/Ctrl+Enter) are consumed instead of stacking newlines, while repeats of a newline gesture (`Shift+Enter`, `mod-enter` mode's bare Enter) keep their native line break. A LIVE composition outranks everything: while `isComposing` / `keyCode === 229` / a tracked composition owns the key, even an Alt or repeated Enter goes straight to the input method (no submit, no consumption). The plain Enter / Cmd+Enter / Shift+Enter behaviour is unchanged.
  - 🧪 `tests/sidechat-composer-guards.spec.tsx` (five chords in both modes, repeats of submit vs newline gestures, 229 left unconsumed, real gestures still working) and `tests/sidechat-composition-priority.spec.tsx` (a live composition outranks Alt/repeat).

- ▶️ **A running side chat can be sent to AND stopped at the same time.** The composer swapped `running ? stop : send`, so while a turn ran the send button simply disappeared and readers concluded they could not queue a follow-up — while Enter always could (the host accepts the message into the thread's inbox). Both controls now stay in the composer bar while a turn runs: sending queues exactly one `sidechat.prompt` and cancels nothing, stopping issues one `sidechat.cancel` and sends nothing. Availability is per control: an empty draft disables sending only and never greys out stop (`busy` alone gates both), and both the draft and the send action survive a stop.
  - 🧪 `tests/sidechat-send-while-running.spec.tsx` (both mounted and un-hidden, send queues without cancelling, stop cancels without sending, empty draft only disables send).

- 📐 **The side chat's transcript text follows the host's content-font setting.** Bubbles, assistant narration and queued bubbles were pinned to `14px/22px`, and the transcript chrome around them (tool and thinking rows, raw tool text, the usage tail, present-card rows, hint and error rows, queue meta) to `12px/18px` — so raising the content size grew only the markdown body and left every supporting line behind, drifting hierarchy and rhythm apart. The body now uses the primary axis (`--dsh-content-font-size` + `--dsh-content-font-delta`) and the chrome the secondary one (`--dsh-content-font-size-secondary` + `--dsh-content-font-delta-secondary`), exactly like the host's own `MessageItem`; colours, spacing and bubble geometry are untouched. The floating pills, the running status line and the hero's primary button deliberately do NOT follow it — they are fixed control steps (`--dsw-font-xs-13` / `--dsw-font-xxs-12`), not transcript prose. Raw tool text now uses `var(--dsw-font-mono, ui-monospace, SFMono-Regular, Menlo, monospace)`: the host never defines `--dsw-font-mono`, so that declaration used to be dropped at computed-value time and code text was never actually monospace. `docs/external-plugin-guide.md` §12 states the boundary (`--dsh-content-font-*` only in type declarations).
  - 🧪 `tests/sidechat-typography-contract.spec.tsx` pins the axis of all 13 rules, the retirement of the fixed 12/13/14px combo tokens, the colour/geometry snapshot, and "content-font variables only in `font`/`font-size`/`line-height`"; `tests/sidechat-pill-typography.spec.tsx` pins that the pills and status line only name font tokens the host actually defines (the invented `--dsw-font-s-12` / `-s-13` names are gone).

- 🪶 **Long side chats mount only a tail window, and scrolling up to read no longer gets yanked back to the bottom.** The transcript used to mount the entire history (every code card, table and image in the DOM) and pinned the scroller to the bottom on every growth — while the host pushes an invalidation about every 250 ms during a streaming turn, so long threads were both slow and impossible to re-read. At most **50 rows are mounted** now (the mapping still produces every row; only the DOM is windowed); the unmounted history collapses into a top spacer (inline px height, linear in the hidden row count) behind a **"Show {hidden} earlier rows"** control that mounts 25 more per activation, retires once nothing is hidden, and can be used until every mapped row is mounted again. Following is an intent: `scrollHeight - clientHeight - scrollTop <= 24` decides it, and while it holds a growth pins to the **bottom offset** (not the raw `scrollHeight`). A reader who scrolled away is not moved by transcript growth — with ONE exception, revealing earlier rows: that commit corrects the offset by the content-height delta (`scrollTop += Δ`, or the new bottom when following), because the rows it inserts above the viewport would otherwise push the line being read away. A **"Back to latest"** pill appears off the tail in a zero-height slot aligned to the content column's right edge (no `bottom: 120px` magic number); the slot lives inside the transcript box and the composer is its sibling, so the pill can never cover the input. New `sideChatRevealEarlier` / `sideChatToLatest` copy in all 21 dictionaries.
  - 🧪 `tests/sidechat-windowed-transcript.spec.tsx` (tail window / linear spacer / reveal step / dictionary copy), `tests/sidechat-scroll-follow.spec.tsx` (near-bottom follow, no yank, back-to-latest) and `tests/sidechat-reveal-anchor.spec.tsx` (offset corrected by the height delta when reading; pinned to the new bottom when following); `tests/sidechat-composer-typing-cost.spec.tsx` still holds "zero row re-renders per keystroke".

- ⌨️ **Configurable submit key for side chats (Enter or Cmd/Ctrl+Enter), plus IME safety and typing cost.** The composer hard-coded "any non-Shift Enter submits", so pressing Enter while a CJK input method was still offering candidates sent a half-composed message; the old check also trusted only `isComposing`, missing Safari's composition-closing keydown that arrives AFTER `compositionend`. The Side card settings page now carries a **Send shortcut** dropdown under the side-chat card's gear (`Enter sends` / `Cmd/Ctrl + Enter sends`, default `Enter`), stored in the feature's own `pluginSettings.sidechat.submitKey` through the existing settings route (no host PrefsSchema field) and followed live by already-mounted tabs. The IME guard now matches the host composer — `isComposing`, the legacy `keyCode === 229`, and a 10 ms grace window after `compositionend` — and outranks the Cmd/Ctrl chord. Two cost fixes ride along: transcript rows are memoized by input (a keystroke no longer re-runs `toolArgsSummary` / `formatTokens` / Markdown rendering for unchanged rows), and `growComposer()`'s forced `scrollHeight` reflow moved to the next frame.

- 🪟 **Windows + WSL workspaces: a UNC path is no longer folded into a drive-relative one.** Re-spelling paths on a Windows base folded every run of separators into one `\`, which also folded the UNC prefix of `\\wsl.localhost\<distro>\...` into `\wsl.localhost\...`; the host's `path.resolve()` then anchored that on its own process drive (`C:\wsl.localhost\...`), so every file opened from a WSL workspace failed with ENOENT. The UNC prefix now survives and only the rest is folded (drive paths are unchanged).
  - 🧪 `tests/worktree-address.spec.ts` adds one case: UNC absolute, workspace-relative, and forward-slash spellings all keep the two leading separators.
- 🗂 **A session cwd that is a Git repository subdirectory is no longer lifted to the repository top** ([#1024](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1024), [#1080](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1080); contributor PR [#1070](https://github.com/omdsh-dev/DSH-better-sidebar/pull/1070) @hy5424): the sidebar root was replaced with `git rev-parse --show-toplevel`, so a relative file link in chat resolved to `<repo>/<file>` instead of `<repo>/<subdir>/<file>` (ENOENT) and file search used the wrong root. The session cwd is now the root as it stands; only linked-worktree evidence from the session's own tool calls replaces it. The cwd is canonicalized first, so symlinked spellings (`/var` vs `/private/var`) cannot make a nested worktree look outside the workspace (#952).

- ⚡ **Mermaid previews of large Markdown documents no longer stall the renderer (layout measurement isolated in a sandboxed iframe)**: mermaid measures label text with `SVGElement.getBBox()` against a node appended to `document.body`, so every measurement flushes the whole DSH document layout — measured on a real desktop host at **59–75 ms per measurement** (15,418 nodes) versus **1 ms** in an empty iframe. A 31-diagram document therefore blocked the main thread for >20 s, tripping the desktop shell's surface watchdog and turning tab restoration into a crash loop. Diagrams now render inside a hidden `sandbox="allow-scripts"` iframe (a self-contained blob: document with the mermaid UMD bundle inlined plus a small postMessage protocol); the parent only sends/receives and sanitizes SVG: **per diagram 1,500–7,300 ms → 30–104 ms, 31 diagrams in ~5 s**, while the client mermaid chunk shrinks from **7.04 MB to 3.69 MB**. A shared render queue (visible/near-viewport diagrams first, the rest filled in on `requestIdleCallback`, 16 ms main-thread yields between renders — **every diagram is still rendered, none degrades to a code block**) and fence-line-sized placeholder skeletons complete the change. Design and measurements: [docs/plans/2026-10-23-mermaid-iframe-isolation.md](docs/plans/2026-10-23-mermaid-iframe-isolation.md).
- ⚡ **Smooth scrolling for large documents**: the render queue pauses while the reader scrolls (resuming 350 ms after the last scroll event) and only serves the preview that is actually on screen — hidden tabs keep placeholders and warm their diagrams when shown again. The two mutation-driven full-document scans (inline HTML pass, heading-anchor pass) coalesce bursts into one pass every 80 ms (previously a scan per mutation, measured at 8–15 ms each); initial near-viewport detection reads every rect in one batch before the swap writes, removing one forced layout per diagram; `.mermaidWrap` gains `content-visibility: auto` + `contain-intrinsic-size` + `contain: layout paint style`, so off-screen diagrams leave layout and paint entirely. Scrolling no longer competes with background renders, document-wide scans or off-screen SVG repaint; diagrams still fill in when the reader stops or scrolls them into view — never as code blocks.
- 🐞 **A failed diagram shows the mermaid parse error inline**: instead of only a generic "Mermaid render failed" label plus the source block (the full error was hidden in the hover title), the error strip now prints the first two lines of mermaid's message (e.g. `Parse error on line 10 ... Expecting 'SEMI', ...`), so a broken fence is found without hunting; the full text stays on the title.
